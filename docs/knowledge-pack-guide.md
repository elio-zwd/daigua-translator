# AI 制作与反馈修正知识包

当前日常入口为[外部 AI 交接提示词](external-ai-handoff.md)，包含源码输入、项目包与通用库双输出、校验和加载方法。下列提取器流程是可选辅助，直接阅读源码制包无需先生成草稿。

插件运行时不使用 AI。制作阶段按以下顺序进行：

1. 确定目标工程范围，直接按文件阅读源码。若选择提取器辅助流程，共享源码场景指定 `--root`，局部候选使用 `--include-locals`；先读 `uncertain.json`，再按文件阅读草稿并回看源码。
2. **AI 先筛选**候选，根据源码填写中文、参数、返回值和限制；排除项记录原因。复杂结构可回看源码后补录并注明来源。
3. **默认直接使用，有问题再反馈。** AI 完成自查和结构校验，不要求用户逐条审核。来源与不确定说明保持可回查；已有人工状态仅记录实际发生过的核验，没有核验就保留原状态，不据此阻止使用。没有依据的推断不能写成事实。
4. 校验器的 `--src` 使用实际源码根目录；使用提取器时与它的 `--root` 保持一致，通过后可 `--out` 导出。通用技术库按新交接说明单独校验。警告不等于已确认。
5. 配置 JSON 绝对路径。验证未查过的本地词条、同名候选和 Bing 回退；已查词条的更新单独记录缓存表现。

```powershell
python extractor/extract.py --proj 'D:\MCU\05_createtask\mdk_v5\course.uvprojx' --root 'D:\MCU' --include-locals --out extractor/out/05_createtask
python validator/validate.py --pack knowledge-packs/05_createtask-pack.json --src 'D:\MCU' --out ready.json
```

正式包沿用五种类别，局部变量仍为 `variable`，保留文件、函数和声明位置构成的 `scope`，不要按名称直接合并。函数体和邻近代码等草稿字段不必写入正式包。

05 的[候选清单](../knowledge-packs/reviews/05_createtask-review.md)及同目录 JSON 保存 AI 决定、来源、排除原因、人工状态、提交号和文件哈希。`source_version` 是制作时真实提交号，哈希描述实际文件快照，不将提交号当作工作区无修改的证明。

更新时由 AI 重新阅读受影响源码，对照旧词条修正，再校验和加载；符号提取器只是可选辅助。历史人工核验状态不自动沿用为新内容的确认，也不因此要求用户重审。独立插件加载新包后使用当前内容。


## 0.4.0 音标补充衔接

中文知识包冻结并通过校验后，由外部 AI 调用 `phonetics/tool.py enrich` 补音标，再处理导出的缺失／待确认清单。使用独立补充文件回填，保留原始包和已有中文，不把符号提取器作为 AI 制包的必要前置步骤。具体命令、技术库格式及数据来源规则见[第一期指南](phase-one-guide.md)。


## 0.5.0：简明用途与通用词库制作规则

本节覆盖旧版“日常完整展示实现说明”的要求，旧知识包仍兼容。

- 新生成或完善的词条、参数增加 `summary_zh`，用一句自然中文解释核心含义或用途；与 `name_zh` 互补，不复述逐行实现。
- `description_zh` 继续保存依据源码编写的详细说明。来源、声明、参数与返回值不删除；频率、引脚、内存大小、当前配置值及实现检查只进入详细说明，不放入日常简明用途。类型宽度、单位等定义本身必要的信息保留，例如“16 位无符号整数”。
- 例：`course_board_init` → `name_zh: 板级初始化`，`summary_zh: 配置开发板的时钟和基础外设，为程序运行做好准备。`。当前项目确有 LED、串口或 DWT，不代表所有板级初始化都包含这些外设。
- 从用户提供的工程代码提炼通用词条时，只抽取跨项目稳定的含义。普通局部变量和业务名称保持项目作用域；不将当前工程的特殊用途写成通用约定。
- 通用词条使用技术库 `format_version: 1`，例如 `token: board_init`、`match: identifier`、`translation: 板级初始化`、`summary_zh: ...`，并保留原有 `reading`、`source` 和 `review_status`。无可靠读法时用 `reading: unknown`，不编造音标。
- 带非空 `summary_zh` 的完整名称词条允许拆词归一化和前缀推测复用；推测仅匹配至少两个完整词段组成的最长后缀，含数字或限定 `symbol` 的技术库条目不参与泛化。`uint16_t` 仍按完整名称精确匹配。
- 更新知识包与对应音标增强包时保持简明用途一致；补音标流程保留所有原始中文字段。用户无需逐条审核，发现问题后更新词库文件。
