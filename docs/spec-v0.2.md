# MCU 代码翻译工具方案草稿

版本：V0.2  
日期：2026 年 11 月 3 日  
用途：确定项目方向与功能边界，可直接修改本文后用于指导开发。

## 1 项目方向

做一个面向 C/C++ 单片机开发的代码翻译工具，通过 MTranCode 自定义翻译服务使用。

**使用时先查本地知识包；没有匹配结果，回退到 MTranCode 自带的 Bing 翻译。插件不接入在线 AI。**

**知识包制作时，由 Antigravity、Codex 等 AI 编程工具先编写并运行源码提取工具，初步整理函数等内容，再由 AI 根据提取结果和必要源码编写中文说明，最终生成本地知识包。**

项目围绕这一套完整流程开发，不划分多期。

## 2 日常使用方式

用户在 MTranCode 中发起翻译，新插件接收待翻译内容，按以下顺序处理。

1. 查询已加载的本地知识包。
2. 找到明确匹配的词条，直接返回中文说明，不发起网络请求。
3. 没有匹配结果，将原始输入交给 MTranCode 自带的 Bing 翻译。
4. Bing 请求失败或断网时，显示翻译失败提示；本地已有词条仍可查询。

| 输入示例 | 处理方式 | 预期结果 |
| --- | --- | --- |
| 知识包已收录的函数名 | 本地查询 | 中文名称、功能及已有参数说明 |
| 知识包已收录的变量名 | 本地查询 | 中文名称、用途及已有类型信息 |
| 未收录的函数或变量名 | MTranCode 自带 Bing 翻译 | 普通翻译结果 |
| 英文注释或普通技术文本 | 本地有完整对应词条则返回，否则回退到 Bing | 中文译文 |

例如，知识包中存在 `NFC_WriteU16LE` 时，直接显示包内解释；没有收录时，交给 Bing 翻译。Bing 结果只是普通译文，不作为已核实的函数功能说明。

使用 MTranCode 现有的翻译入口。独立的函数或变量悬停功能不纳入本方案。

## 3 知识包怎样制作

知识包由 AI 编程工具协助制作，不要求再开发一个带模型配置、批量 AI 调用和任务管理界面的独立软件。

### 3.1 先让 AI 做提取工具

在 Antigravity 或 Codex 中提供 MCU 工程目录，让 AI 编写、调试并运行一个本地提取脚本。

脚本负责初步整理源码中的函数、变量及相关内容，输出便于 AI 阅读的中间文件。主要内容包括：

- 函数名称、声明、参数、返回类型、已有注释、函数实现和来源位置。
- 变量名称、类型、已有注释、所在文件或函数，以及解释所需的邻近代码。
- 工程中实际需要的宏、枚举和类型定义，可一并提取。

过滤构建产物和重复声明；`i`、`j`、`tmp` 等普通局部变量默认不单独做词条。保留有业务含义的局部变量。

工具选型以能正确处理目标工程为准，不预先强制引入复杂解析框架。提取不到或不能确认的内容单独列出，避免静默生成错误结果。

### 3.2 再让 AI 根据内容写中文

让 Antigravity 或 Codex 读取中间文件，必要时回看对应源码，逐批整理中文词条。

函数说明主要回答：

- 中文名称是什么。
- 这个函数实际做什么。
- 参数和返回值表示什么。
- 是否有源码明确体现、且值得说明的使用限制。

变量说明主要回答：

- 中文名称是什么。
- 变量用来保存什么。
- 类型是什么。
- 取值含义是什么，但只填写能从源码或注释中确认的内容。

**工具负责提取事实，AI 负责理解和中文表达。没有依据的内容留空或标记待确认。**

按文件或模块分批处理即可，不要求一次把整个工程交给 AI。

### 3.3 校验后导出知识包

由工具检查格式、必填字段、重复词条和来源信息，再导出 JSON 知识包。人工可以直接修改词条中的中文内容。

更新时重新提取受影响文件，让 AI 修改对应词条，再重新导出。不增加专门的自动化 AI 生产平台。

## 4 知识包内容

先用一份或少量 JSON 文件保存词条。重点是函数和变量，其他符号按工程实际需要收录。

| 字段 | 用途 |
| --- | --- |
| 原始名称 | 用于查询，保留大小写 |
| 类别 | 函数、变量、宏、枚举、类型等 |
| 中文名称 | 简短中文释义 |
| 功能或用途 | 根据源码整理的解释 |
| 声明或类型 | 保存函数签名或变量类型 |
| 参数说明 | 函数使用；没有参数则留空 |
| 返回值说明 | 函数使用；没有返回值则留空 |
| 所属模块或作用域 | 区分同名符号 |
| 来源 | 工程或 SDK 名称、版本、相对文件路径和位置 |
| 待确认说明 | 仅在内容存在疑问时填写 |

知识包自身保存名称、版本和适用工程或 SDK 信息。词条来源位置用于检查依据，不等于实现函数调用图或变量读写追踪。

### 知识包 JSON 结构示例

```json
{
  "name": "示例工程知识包",
  "version": "1.0",
  "source_version": "工程版本或提交号",
  "entries": [
    {
      "symbol": "NFC_WriteU16LE",
      "kind": "function",
      "name_zh": "NFC 小端序 16 位无符号数写入",
      "description_zh": "将指定的 16 位无符号数按小端序写入目标缓冲区。",
      "declaration": "void NFC_WriteU16LE(uint8_t *dst, uint16_t value)",
      "parameters": [
        { "name": "dst", "description_zh": "目标缓冲区" },
        { "name": "value", "description_zh": "待写入数值" }
      ],
      "returns_zh": "无返回值",
      "scope": "nfc_codec",
      "source": { "file": "src/nfc_codec.c", "line": 42 },
      "uncertainty": ""
    }
  ]
}
```

## 5 本地匹配规则

本地包用于查询已整理好的知识，不承担任意文本的完整离线翻译。

1. 优先按原始符号精确匹配，保留 C/C++ 大小写差异。
2. 支持忽略首尾空格、剥离函数名末尾的空括号，例如 `Motor_Start()` 可查询 `Motor_Start`。
3. 同名词条存在歧义时，显示模块和来源供辨认；没有可靠依据时，不自动选定其中一条。
4. 长文本不能因为包含某个已收录函数名，就只返回该函数词条；无法完整匹配时，将整段原文交给 Bing 翻译。

插件提供加载或重新加载本地包的入口。可选用一份工程包，并按需补充通用包，不引入自动识别 SDK 和工程的复杂机制。

## 6 Bing 回退与最小配置

运行时只保留"查本地包，未命中则回退到 Bing"这一条流程。

- 复用 MTranCode 自带的 Bing 翻译能力，不另做一套 Bing 客户端或账号配置。
- 将未命中的原始输入交给 Bing，不用本地部分匹配结果替换原文。
- Bing 返回的译文直接用于本次显示，不自动写入正式知识包。
- 插件只保留本地知识包路径及重新加载入口；Bing 沿用宿主已有设置。

开发时需核对 MTranCode 的翻译服务调用方式，实现自动回退，并避免再次调用本地插件造成循环。本文确定的是目标行为，具体接法以源码核实结果为准。

**Antigravity、Codex 只用于开发工具和制作知识包，不参与日常翻译请求。**

## 8 功能边界

插件运行时不接入在线 AI，不提供 API Key、模型或 AI 服务地址配置。

本方案不包含函数调用关系、变量读写位置追踪、中断与任务关系、状态机分析、独立 Hover Provider、本地大模型服务、向量数据库或独立桌面知识包管理软件。

说明某个中断函数的基本作用、翻译某个状态枚举，仍属于普通词条内容；不延伸为关系分析。

## 9 完成标准

- 在 MTranCode 中能选择并使用这个翻译服务。
- 已收录符号能返回本地中文说明，断网后仍可使用。
- 未收录内容能自动回退到 MTranCode 自带的 Bing 翻译，无须用户手动切换翻译源。
- 插件没有在线 AI 配置，不发送 AI 请求；Bing 翻译结果不自动写入知识包。
- 同名符号不错误合并，长文本不因局部命中而丢失其余内容。
- 提取工具能处理一个真实 MCU 工程，并保留解释所需的源码和来源。
- 能在 Antigravity 或 Codex 中根据提取内容完成中文词条，再导出、加载和更新知识包。
