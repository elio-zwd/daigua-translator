# 0.6.1：词库目录配置未注册修复与相邻流程检查

## 用户问题与修复

用户在词库目录入口遇到：`CodeExpectedError: 没有注册配置 daiguaTranslate.libraryDirectory，因此无法写入 用户设置。`。0.6.0 安装包已经声明该项，但原实现依赖当前窗口的配置登记和设置写入同时可用，不能处理升级窗口中登记状态不同步的情况。

0.6.1 新增目录设置适配层：正常情况下使用标准设置；目录项未注册或写入返回明确的未注册错误时，等待扩展持久状态保存成功后立即加载目录。用户级和工作区级选择分别保存；配置恢复后同步标准设置，明确的新设置值优先。一般权限或存储失败仍报错，不误报成功。扩展状态只保存目录路径，不保存词库数据。

相邻流程修复和补强：

- 切换到无法加载的另一个目录时，跟随面板清除旧目录结果并重新查询；锁定内容按原约定保留。
- 工作区原值格式错误时，新选择写回工作区，避免仅更新用户设置后仍被工作区值遮蔽。
- Windows 路径按大小写及分隔符归一化比较，避免将同一原目录的写法变化误判为另一次设置修改，丢弃待恢复选择。
- 目录监听以目录根递归监听、按清单路径过滤，覆盖首次创建的启用子目录；未启用文件不会触发词库重载。
- 真实安装测试从产品所属 API 替代目录选择器，不操作原生文件对话框。

## 实际验证

环境：Windows 10 x64、PowerShell 7、VS Code 1.107.1。全部安装、配置写入及持久化测试均使用临时配置目录，未改动日常 VS Code 配置。

| Python 测试 | 39 项通过 |

| 未注册与跨进程恢复 | 两阶段均 passed=true，见下文 |

恢复回归先安装临时修改配置声明的测试包，真实重现原生写入错误，再通过产品的目录入口保存并验证悬停、面板。关闭后，在同一临时用户配置中安装正常包，验证目录从持久状态恢复并同步到用户设置，再验证查询。

VS Code 的 `extensionTestsPath` 会启用内存存储，不能证明跨进程持久化。因此本项改为普通隔离窗口的自动激活驱动，实际写盘并关闭、重开；同时按 Windows 规则比较恢复后的路径。

最终证据：

- 安装宿主：`C:\Users\005869\AppData\Local\Temp\daigua-host-195805c3fb5d499baa8823091843e076\report.json`。
- 界面：`C:\Users\005869\AppData\Local\Temp\daigua-ui-DE0XJf\report.json`，同目录保留截图。
- 恢复前后：`C:\Users\005869\AppData\Local\Temp\daigua-recovery-2f97035e9a054ddaa0d482df66943653\report-missing.json`、`report-restored.json`，两者 passed=true。目录另有完整启动日志。
- 探索阶段的失败与中断证据保留在相应 `daigua-recovery-*` 临时目录；没有把内存存储模式的结果计为持久化通过。
