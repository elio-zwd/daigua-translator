## 2. 问题与现有实现

示例名称：`app_ble_adv_msg_handler`。
当前面板只显示「广播消息处理」和 `ble` 的原词补充。
整名音标连续排列，缺少逐词中文对照。

| 位置 | 已核对的现状 | 改造目的 |
| --- | --- | --- |
| `plugin/src/daigua-translate.ts` | `lookupResult()` 命中源码后直接返回 | 保留整名优先，另行补充面板学习数据 |
| `plugin/src/offline-dictionary.ts` | `nameDetails()` 只收集缩写原词和命名前缀 | 面板逐词展示不能只依赖 `nameDetails` |
| `plugin/src/offline-dictionary.ts` | `explainResult()` 可能先返回整名约定 | 提取不受整名命中短路影响的逐词查询能力 |
| `plugin/src/result-renderer.ts` | `pronunciationText()` 使用 `·` 拼接 | 新增面板渲染，不全局替换悬停格式 |
| `plugin/src/webviews.ts` | 面板刷新替换内容区 HTML | 保留用户阅读位置，防止展开内容重复闪动 |
| `dictionaries/words/02-general-terms.json` | `BLE` 为 `insensitive`，`ADV` 为 `exact` | 正确区分已命中释义与大小写推测 |

`dictionaries/` 是独立 Git 仓库。
参考图中的 `app`、`msg` 释义不等于当前词库已有数据。
参考图中的音标也不是新增词条的证据。

## 3. 目标与边界

目标：英文基础较弱的读者能逐词理解代码名称。
整名释义解释「这个名称在代码中表示什么」。
逐词学习解释「名称中的每个词是什么意思、怎么读」。

本次包含：

- 固定面板的信息层级、逐词释义和分行音标。
- 缩写全称、原词逐词释义和原词逐词音标。
- 有标记的本地名称推测。
- 跟随、锁定、复制名称与设置入口的衔接。
- 多候选、缺失、错误、主题和窄面板适配。
- 必要的词库维护、兼容处理与验证。

本次不包含：

- 重做悬停、翻译引擎或整个设置页。
- 语音播放、自动朗读、收藏、测验或学习历史。
- 接入运行时 AI 服务、账号体系或 API Key。
- 在日常结果中加入声明、参数表或源码路径。
- 全局忽略大小写或自动修改用户词库。

## 4. 结果结构与查询流程

### F01：整名释义保持优先

整名查询顺序沿用现有规则。
源码符号、命名约定、词语与联网回退的优先级不变。
逐词补充不能改变 `kind`、`match` 或候选排序。
逐词查询失败不能丢弃已获得的整名结果。

面板的结果顺序：

1. 工具栏。
2. 原始英文名称。
3. 整名释义、解释类型与工程标签。
4. 逐词学习。
5. 简短提示。
6. 调试信息，受现有调试开关控制。

旧包缺少 `summary_zh` 时，只显示已有中文名。
系统不截取 `description_zh` 生成用途。
没有整名释义时，学习区仍可显示。
这时顶部显示「暂无完整名称释义，可查看逐词理解」。
纯离线拆词结果不伪装成源码释义。

### F02：独立生成面板学习数据

面板对单个代码名称生成学习数据。
源码、完整命名约定、离线拆词和联网结果均适用。
整名命中不再阻断面板逐词学习。

系统复用 `splitIdentifier()` 的边界规则。
系统保留词段顺序、原始大小写和重复位置。
例如 `msg_msg_handler` 必须保留两个 `msg`。
分隔符不作为独立词条显示。

建议将逐词查询提取为独立服务。
禁止直接重复调用会返回整名结果的 `explainResult()`。
面板学习数据不能回写共享的 `components` 改变悬停。
悬停继续使用现有渲染数据与逻辑。
新学习数据优先按面板需要加载。

### F03：逐词释义优先级

| 顺序 | 来源 | 日常显示 |
| --- | --- | --- |
| 1 | 清单启用且匹配的词语条目、明确的命名规则 | 主词义及可用其余词义 |
| 2 | 符合 F04 且满足适用条件的技术缩写推测 | 中文含义旁显示「名称推测」 |
| 3 | 已配置 ECDICT 的匹配词条 | 首个非空词义为主词义，其余直接列出 |
| 4 | 无可用依据 | 「释义暂缺」 |

仅为单字母前缀命中的普通词典义不作为命名含义。
命名前缀必须满足现有边界规则。
例如 `p_mac` 的 `p` 不解释为便士。

`panel_only` 规则只补充面板，不触发整名联网优先级变化。
启用文件的优先顺序继续遵守独立词库规则。
同义项只去除完全相同的文字，不做语义合并。
释义栏保留词性缩写和必要单位。

技术缩写推测优先于普通词典的跨领域义项。
例如在蓝牙名称中，不能让「副词」挤掉 `adv` 的广播推测。
普通词典的不同含义作为「其他词典含义」直接列出。
这些含义不纳入技术缩写的同义词列表。

### F04：缩写名称推测

系统使用本地、确定性的规则推测名称。
系统不调用 AI，也不逐词调用联网翻译。
推测以清单启用的数据为依据，不增加隐藏词库。

允许的推测路径：

- 忽略大小写后，找到唯一的缩写词条候选。
- 根据词库声明的缩写映射找到原词。
- 使用明确记录适用条件的本地推测规则。

适用条件必须能从当前查询数据验证。
例如规则可要求名称同时包含 `ble` 和 `adv`。
规则可沿用现有 `symbol` 限定完整名称。
禁止仅凭路径包含某个英文片段认定技术语境。

若候选有领域限制，系统必须先检查适用条件。
条件无法验证时，不将领域义项作为唯一主词义。
系统可将该候选放入「可能含义」并说明适用语境。
此时保留普通词典的主词义，不静默覆盖。

大小写推测不改变 `exact` 的正式匹配语义。
例如小写 `adv` 参考大写 `ADV`，仍标为「名称推测」。
若维护者补充了正式的小写规则，则走正常匹配。
是否将 `ADV` 改为 `insensitive`，必须先核对适用范围。

`app → application`、`msg → message` 需要数据依据。
禁止在 TypeScript 中硬编码演示专用答案。
若现有格式不能声明推测条件，应增加可选规则字段。
实施者必须同步校验器、文档和旧包兼容测试。
规则只能放在清单启用的独立词库中。
禁止通过未启用的制作报告或历史包提供依据。

推测候选存在歧义时，不自动选择第一条。
面板显示「名称推测 · 可能含义」并列出不同候选。
候选保留必要的适用说明，候选数不强行截断。
缺少规则或候选时显示「释义暂缺」。
禁止用任意词的首字母组合无限搜索全称。
禁止把其他名称中的相似片段当作本词的证据。

推测的中文、全称和全称词义须标明所属推测分支。
有可靠读音不代表推测词义已经核实。
底部常驻提示不能替代词条旁的「名称推测」标签。
推测不能覆盖已匹配的词语库和命名规则。
已有完整名称后缀推测继续使用原规则。

### F05：音标与词段对齐

每个词段直接显示自己的音标。
系统不在顶部重复显示完整音标长串。
拼字母读法仍显示「拼字母」。
不发音规则有明确依据时显示「不发音」。

原有源码音标优先于自动补充音标。
补充仍遵守 `supplementPronunciation()` 的保护原则。
系统按词段位置和原文匹配，不能只按小写文本连接。
重复词段不能互相覆盖。
系统不能把整名读音机械分配给多个词段。

无法对齐的原始音标保留在调试信息中。
面板显示简短提示「部分读音无法逐词对应」。

| 读音状态 | 面板文字 |
| --- | --- |
| 可靠单词读音 | `/音标/` |
| 可靠字母读音 | `/音标/ · 拼字母` |
| 有依据的不发音 | 「不发音」 |
| 无可靠读音或冲突 | 「音标暂缺」 |
| 数字或未标注型号 | 「未标注读音」 |

多个有效音标冲突时不随机选取。
系统保留冲突记录，日常显示缺失提示。
音标原值不因外观而擅自改写。
口音与来源限制继续放在设置说明。

### F06：缩写全称和原词

缩写行直接显示有依据的英文全称。
全称下方直接展开各个原词的中文和音标。
英文原词按全称中的顺序排列。
例如 `Bluetooth Low Energy` 下显示 3 个原词行。
原词释义沿用词语查询，不递归展开原词的缩写。
推测全称整体显示「名称推测」。

原词音标使用原词的数据。
禁止将 `ble` 的字母音标当作 `Bluetooth` 的音标。

全称只有部分读音时，显示「部分音标暂缺」。
缺失的原词行仍显示「音标暂缺」。
全部读音缺失时，汇总显示「原词音标暂缺」。

原词中文缺失时显示「释义暂缺」。
没有全称时，不创建空的原词区域。
原词的其余词义也直接列出。

### F07：其余词义与特殊名称

主词义先显示，其余词义以列表直接显示。
默认不折叠，不增加「展开其余词义」按钮。
长词义使用自然换行，不截断完整内容。
整个面板使用纵向滚动，不为每个词条创建滚动框。

单个词名称只显示一份词义和音标。
若顶部已有相同的词典释义，则学习区承担该份展示。
源码中文用途与单词释义不同，应各保留一份。

数字保留原文，不能编造读音。
类型中的宽度属于名称含义，应予保留。
例如 `uint16_t` 的整名中文必须保留「16 位」。
逐词拆分不能替换类型的完整解释。
`t` 的类型后缀含义必须有命名规则依据。

普通句子、多行选区继续使用文本翻译界面。
系统不将普通句子当作代码名称逐词展开。

## 5. 多候选与工程上下文

本工程候选排在前面。
其他工程最多展示 3 条不同整名释义。
现有精确去重规则继续生效。
参数及局部变量保留必要的所属函数。

整名候选卡依次排列，不用默认隐藏的候选分页。
工程标签属于各自候选，不能放成全局标签。
候选卡不再重复整名音标长串。

全部候选之后只放一份逐词学习区。
逐词学习区不宣称属于任何一个源码候选。
规则的 `symbol` 限定继续生效。
名称规则无法区别同名函数的实际行为。
出现多个缩写推测含义时，按 F04 展示歧义。
完整路径和合并来源只进入调试信息。

## 6. 面板交互与状态

| 场景 | 必须行为 |
| --- | --- |
| 跟随光标 | 保留现有 350 ms 防抖，不抢编辑器焦点 |
| 锁定 | 保留当前名称、候选和学习区，忽略光标移动 |
| 解锁 | 按当前编辑器位置查询并更新 |
| 主动打开指定名称 | 显示请求名称，即使面板原先锁定 |
| 复制名称 | 复制完整原始名称，不带空格拼接或中文 |
| 设置 | 打开现有设置页，保留面板内容 |
| 无可查名称 | 显示现有空状态，不残留上一个词的释义 |
| 学习数据加载中 | 先显示整名结果，学习区显示「正在整理逐词释义…」 |
| 学习数据失败 | 保留整名结果，显示「逐词释义暂不可用」 |
| 新名称更新 | 滚动回内容顶部 |
| 同名称补充完成 | 保留滚动位置、焦点和文本选择，避免整页闪动 |
| 调试开关变化 | 刷新调试区，不重置当前名称与阅读位置 |

系统使用请求序号、文档版本和词库版本校验结果。
旧请求不能覆盖新名称。
词库切换后，旧学习结果不能混入新结果。
锁定状态下允许同一请求的学习补充完成。
后续词库变化不自动替换已锁定的阅读快照。
解锁或主动重新查询后，再使用新词库。

关闭联网后，逐词学习仍使用本地数据。
`off` 模式继续控制整名自动查询资格。
已命中的源码结果允许补充本地面板学习数据。
`off` 模式下，未命中源码不能因学习补充而自动出结果。

主动本地查询不发送网络请求。
自动联网补充整名的现有流程继续保留。
本次不新增逐词联网请求。

## 7. 建议的数据结构与职责

本节是实现建议，字段名允许按源码调整。
产品行为与验收条件不随字段名改变。
优先增加内部视图模型，避免重写知识包格式。

实际内部模型见 [panel-learning.ts](../../plugin/src/panel-learning.ts)。
实现使用分支对象关联词义、全称和原词，避免混用多义候选。
词语格式的新增可选字段见 [目录格式说明](../library-directory-0.6.0.md)。

```ts
interface PanelLearning {
  state: 'loading' | 'ready' | 'unavailable';
  symbol: string;
  items: LearningItem[];
  diagnostics: string[];
}
interface LearningItem {
  id: string; // 同一请求内稳定，包含词段位置
  index: number;
  text: string;
  meanings: LearningMeaning[]; // 全部默认显示
  pronunciation?: Pronunciation;
  expansions: LearningExpansion[]; // 每个候选独立关联
}
interface LearningMeaning {
  id: string;
  text: string;
  basis: 'library' | 'dictionary' | 'inferred' | 'missing';
  source: string;
  ruleId?: string;
}
interface LearningExpansion {
  text: string;
  inferred: boolean;
  meaningIds: string[]; // 绑定本分支，防止混用多义词义
  words: LearningItem[]; // 只展示一层，不递归展开
}
```

词义 ID 必须与 `meaningIds` 对应。
来源、规则、缺失和审核状态保留在底层数据。
日常界面只展示必要的解释类型和推测标签。
`inferred` 不能写成 `confirmed`。

面板渲染器接收学习模型，不负责查词。
Webview 只处理展示和既有用户操作。
词库文件与字典读取在扩展宿主中完成。

| 模块 | 建议工作 |
| --- | --- |
| `identifier-words.ts` | 复用拆词边界，必要时增加带位置的辅助接口 |
| `offline-dictionary.ts` | 抽取逐词查询、原词查询与推测规则 |
| `query-result.ts` 或新增内部模型模块 | 定义面板学习数据，保持旧结果兼容 |
| `daigua-translate.ts` | 衔接整名结果与面板补充，隔离悬停路径 |
| `pronunciation.ts` | 复用补充保护，校验逐词对齐 |
| `result-renderer.ts` | 新增学习区 HTML，不改变 `hoverMarkdown()` 输出 |
| `webviews.ts` | 工具栏、布局、局部刷新与阅读状态 |
| `extension.ts` | 面板入口、请求失效、锁定与跟随协调 |
| 独立词库和校验工具 | 数据补充、规则适用条件、兼容校验 |

缓存键必须包含有效词库版本和完整名称。
若结果依赖工程上下文，缓存键还需包含工程标识。
系统复用当前 ECDICT 分片缓存，不加载完整 CSV。
同次查询中的重复词段可以复用读取，展示仍保留位置。
实施者应记录冷查询和缓存查询耗时。

## 8. 词库工作与示例验收数据

示例目标是帮助理解 `app_ble_adv_msg_handler`。
